MAPA ESTRUCTURAL

¿Por qué existen estos archivos y qué hace cada uno?

ARQUITECTURA
La regla de oro: Si colocas 500 líneas en un solo archivo index.js, el código se vuelve imposible de testear, depurar y escalar. Una API profesional desacopla responsabilidades para que cada archivo tenga una sola razón para cambiar (Principio SRP).

1. package.json

El Pasaporte: Declara el tipo de módulo ("type": "module" para usar import/export modernos), los scripts de ejecución y las librerías necesarias.

2. src/app.js

El Ensamblador: Configura middlewares (JSON, cookies, CORS, SemVer) y enlaza las rutas. No abre puertos de red, permitiendo probar la app en memoria.

3. src/server.js

El Escuchador de Red: Lee el puerto del entorno (process.env.PORT), ejecuta app.listen() y gestiona el apagado ordenado (Graceful Shutdown).

4. src/routes/orden.routes.js

El Semáforo: Conecta los métodos HTTP (GET, POST, PATCH, DELETE) con sus respectivos controladores y validadores. Define las URLs públicas.

5. src/controllers/orden.controller.js

El Embajador HTTP: Extrae datos de req.body, req.params, req.query, los envía al servicio y devuelve res.status().json() y cookies.

6. src/dtos/orden.dto.js

El Filtro de Seguridad: Desecha campos maliciosos enviados por el cliente (como esAdmin: true) y normaliza strings con trim() e inmutabilidad.

7. src/validators/orden.validator.js

El Portero: Utiliza express-validator para rechazar de inmediato datos con formatos erróneos (400 Bad Request) antes de tocar el controlador.

8. src/services/orden.service.js

El Cerebro de Negocio: Calcula impuestos (IVA 12%), valida transiciones de estado, ejecuta simulaciones de prueba (/preview) e introspección de esquemas (/schema).

9. src/models/orden.model.js

La Bóveda de Datos: Gestiona la colección de órdenes, generación de IDs únicos, filtrado y persistencia independiente del motor de base de datos.

10. src/middlewares/error.middleware.js

La Red de Salvamento: Captura peticiones a URLs inexistentes (404) y excepciones inesperadas de 4 argumentos (err, req, res, next) evitando caídas del servidor.

02 / DTOs & SEGURIDAD · 4 MIN

El Filtro de Datos contra Inyección (Whitelist)

Vulnerabilidad de Asignación Masiva: Si pasas req.body directamente a tu base de datos, un usuario curioso puede enviar { "esAdmin": true, "total": 0.01 }. El DTO (Data Transfer Object) actúa como un escudo que sólo copia propiedades explícitamente autorizadas y congela el objeto con Object.freeze().
api/src/dtos/orden.dto.js · (Haz clic en cualquier línea para inspeccionar) 


1export class CrearOrdenDTO {


2  constructor(payload = {}) {


3    this.cliente = String(payload.cliente || "").trim();


4    this.servicio = String(payload.servicio || "").trim().toLowerCase();


5    this.monto = Number(payload.monto);


6    this.prioridad = payload.prioridad ? String(payload.prioridad).trim().toLowerCase() : "media";


7    this.estado = "borrador";// Forzado por seguridad


8    Object.freeze(this);


9  }


10}

04 / MODELO & PERSISTENCIA · 4 MIN

La Bóveda de Datos Desacoplada

Patrón Repositorio: Ni las rutas ni los controladores deben escribir consultas a bases de datos directamente. El OrdenModel encapsula el almacenamiento, ya sea en memoria, PostgreSQL o MongoDB, permitiendo cambiar el motor de datos sin tocar una sola línea del controlador.
api/src/models/orden.model.js · (Haz clic en cualquier línea para inspeccionar) 


1export class OrdenModel {


2  static async find(filtros = {}) {


3    let res = [...ordenesDb];


4    if (filtros.estado) res = res.filter((o) => o.estado === filtros.estado);


5    return res.sort((a, b) => new Date(b.createdAt) - new Date(a.createdAt));


6  }


7  static async create(datos) {


8    const codigo = `ORD-2026-${String(ordenesDb.length + 1).padStart(3, "0")}`;


9    const nueva = { id: `ord-${Date.now().toString(16)}`, codigo, ...datos, createdAt: new Date().toISOString() };


10    ordenesDb.unshift(nueva);


11    return { ...nueva };


12  }


13}

05 / SERVICIOS & CUSTOM OMS · 5 MIN

El Cerebro: Cálculos, Simulación y Esquemas Dinámicos

La Magia de las APIs Custom en OMS: Además del CRUD típico, los backends empresariales necesitan endpoints especializados: /preview calcula impuestos y valida reglas de negocio sin escribir en la base de datos (Dry-Run), y /schema devuelve la definición de campos para que las interfaces frontend generen formularios dinámicos automáticamente.
api/src/services/orden.service.js · (Haz clic en cualquier línea para inspeccionar) 


1const TASA_IVA = 0.12;


2export class OrdenService {


3  static async crear(dto) {


4    const impuesto = Number((dto.monto * TASA_IVA).toFixed(2));


5    const total = Number((dto.monto + impuesto).toFixed(2));


6    return await OrdenModel.create({ ...dto, impuesto, total });


7  }


8  static simularPreview(payload) {


9    const subtotal = Number(payload.monto || 0);


10    return { simulacion: true, totalesCalculados: { subtotal, total: subtotal * 1.12 } };


11  }


12  static obtenerEsquema() { return OrdenModel.getSchema(); }


13}

06 / CONTROLADOR, RUTAS & COOKIES · 5 MIN

El Conector HTTP y la Auditoría con Cookies Seguras

Cookies Seguras en Backend: Al crear una orden, el controlador registra quién fue el último operador en una cookie HTTP con flags httpOnly: true (inmune a robo por JavaScript malicioso en el navegador / XSS) y sameSite: 'lax' (protección contra CSRF).
api/src/controllers/orden.controller.js · (Haz clic en cualquier línea para inspeccionar) 


1static async crear(req, res, next) {


2  try {


3    const dto = new CrearOrdenDTO(req.body);


4    const nuevaOrden = await OrdenService.crear(dto);


5    res.cookie("ultimoOperador", dto.operador, { httpOnly: true, sameSite: "lax" });


6    res.status(201).json({ mensaje: "Orden creada con éxito", data: nuevaOrden });


7  } catch (error) { next(error); }


8}

DICCIONARIO CONCEPTUAL

📖 Glosario de Términos Node.js & Express para Estudiantes

GLOSARIO
req (Request)
Objeto que representa la petición HTTP que llega desde el cliente (navegador, cURL, frontend). Contiene req.body, req.params, req.query, req.headers y req.cookies.
res (Response)
Objeto que permite construir y enviar la respuesta al cliente. Métodos comunes: res.status(codigo), res.json(objeto), res.send() y res.cookie().
next()
Función que le indica a Express que el middleware actual concluyó su tarea y que debe ceder el control al siguiente middleware en la cadena. Si le pasas un argumento como next(error), salta directamente al manejador global de errores.
Middleware
Función intermedia que se ejecuta en el camino entre la llegada de la petición y la respuesta final. Se utiliza para logging, autenticación, parsing de JSON, validaciones de seguridad o inyección de cabeceras.
app.use()
Método de Express para registrar middlewares o sub-enrutadores. Puede aplicarse de forma global a todas las rutas o con un prefijo específico (como app.use('/api/v1/oms', router)).
express.Router()
Crea un mini-enrutador aislado e independiente que permite agrupar rutas de una misma entidad en su propio archivo, desacoplando la definición de URLs del archivo principal app.js.
async / await
Sintaxis moderna de JavaScript que facilita el trabajo con operaciones asíncronas (como consultas a base de datos o lectura de archivos) haciendo que el código parezca síncrono sin bloquear el Event Loop de Node.js.
DTO (Data Transfer Object)
Objeto que transporta datos entre procesos o capas. En seguridad web, actúa como lista blanca (whitelist) para filtrar atributos peligrosos o no autorizados enviados por atacantes en el cuerpo de la petición.
HttpOnly Cookie
Cookie HTTP marcada con el flag HttpOnly. Esta bandera impide que scripts de JavaScript en el navegador (como código inyectado por ataques XSS) lean o roben la cookie, manteniéndola protegida en el encabezado de red.
SemVer (Semantic Versioning)
Convención estándar de versionado con formato MAJOR.MINOR.PATCH (ej: 1.0.0). Comunica cambios que rompen compatibilidad (MAJOR), nuevas funcionalidades compatibles (MINOR) o correcciones de bugs (PATCH).
Graceful Shutdown
Técnica de apagado ordenado donde el servidor captura señales del sistema operativo (SIGINT, SIGTERM), detiene la recepción de nuevas conexiones y espera a que las peticiones en curso terminen antes de matar el proceso Node.
Object.freeze()
Método de JavaScript que 'congela' un objeto, impidiendo que se agreguen nuevas propiedades, se eliminen existentes o se cambien sus valores. Esencial para garantizar inmutabilidad en DTOs.
